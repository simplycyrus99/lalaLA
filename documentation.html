Two deliberate visual systems

The selected theme is saved across pages.

Design record

Why every choice was made this way.

This page exists because deliberate design has to be explainable, not just felt. Every section below answers a "why" question a reader might reasonably ask.

1. Curatorial model

Collection unit

Each item is a real filming location from a single anchor work, La La Land (2016). Unlike a multi-film collection, every record shares one director, one year and one genre profile — so the model instead differentiates locations by which song or scene they belong to and when they appear on screen.

Visitor task

Identify the place, reach it safely (or safely view it from a distance, where a hike or working studio makes that the only option), reproduce or analyse the camera direction, read an interpretation appropriate to the visitor, and inspect structured metadata.

Geographic scope

All fifteen stops lie across the Los Angeles region — downtown, Pasadena/South Pasadena, Griffith Park, Hollywood, Burbank, Beverly Grove, the South Bay and Long Beach — and form a plausible, if ambitious, one-day car itinerary.

Ethics

A working studio backlot, a closed theatre and an isolated hiking trail are each flagged with an explicit access note rather than presented as ordinary walk-up stops. The interface repeats these notes rather than burying them once in a footnote.

2. Narratives

The One-Day Reel Road

Purpose: practical sequential navigation, grouped by neighbourhood, starting downtown and ending in Long Beach to minimise backtracking.

Screen Order

Purpose: this project's required historical/chronological narrative. For a single-film collection, "historical time line" is reinterpreted as the film's own internal timeline — the order these places appear on screen, by timestamp, rather than a multi-decade period sequence. This is a deliberate substitution, not an oversight: a one-film project has no multi-era history to sequence, so the closest equivalent is the story's own chronology.

Order-dependent interface

Previous/next controls are recalculated from the selected narrative. The same item therefore has different neighbours and a different interpretive framing depending on which of the two orders is active.

3. Two visual themes

NOIR CASE FILE
1940s police dossier / newspaper evidence
Monospace typography, double rules, side binding, grayscale images, square controls.
TECHNICOLOR MUSICAL
La La Land's own sunset-and-starlight palette
Twilight purple into sunset orange, gold starlight, rounded frames, centered composition.
Justification: the two themes sit at opposite ends of how this same city has actually been pictured. Noir Case File, heavily inspired by one of my favorite games being LA Noir, treats Los Angeles the way an early-20th-century evidence dossier or archive print would: grayscale, hard rectangles, a single rubber-stamp red, typewriter data, everything pinned to a strict left edge. Technicolor Musical instead takes the film's own onscreen register — the twilight-purple-into-sunset-orange sky of its poster, gold starlight, soft rounded frames — and lets it govern rounded corners, centered composition and a warm gradient wash rather than just a swapped color variable. The two are deliberately opposite on every axis (monochrome vs. color, hard-edged vs. rounded, left-bound vs. centered, typewriter vs. script) so that switching themes reads as switching *eras and lenses* on the same fifteen stops, not just a palette toggle.

4. Reading grid

The location page produces nine item-specific texts from two independent controls:

Very brief Mid-size Long
Young / introductory Friendly orientation + scene clue Adds meaning + memorable fact Adds production context + safe field task
General / average Concise interpretation Standard visitor text Full curatorial account
Scholar / advanced Catalog-style abstract Spatial + interpretive analysis Production, architecture, metadata and field protocol

The text is assembled from location-specific fields (summary, scene, significance, context, trivia, shot instruction); it is not a generic lorem-ipsum expansion. This keeps all nine combinations systematic and maintainable from one dataset.

5. Metadata model

The model combines Schema.org types (Place, PostalAddress, GeoCoordinates, Movie, Person) with project-specific properties for camera orientation, screen timestamp and musical number. Dublin Core is referenced for editorial provenance/source tracking.

Place
 ├─ name, address, geo
 ├─ subjectOf → Movie (La La Land, 2016, dir. Damien Chazelle)
 │   ├─ song / scene, screenTime, screenOrder
 ├─ shotFacing
 ├─ viewpoint
 ├─ accessibility, visitMinutes, bestTime
 ├─ films (other screen appearances of the same real place)
 ├─ gallery (unbounded array of {src, caption} photos)
 └─ sources

Machine-readable files are available in data/locations.json (canonical source) and data/locations.csv (flat export for spreadsheet use). Earlier drafts of this project also generated JSON-LD, GeoJSON and GPX mirrors of the same sixteen fields; these were deliberately dropped as redundant duplication of one dataset that a solo author would otherwise need to keep in sync by hand.

7. Technical architecture

Declarative content

All location information lives in one structured dataset (data/locations.json). Pages render from the same data, reducing inconsistency between map, itinerary and viewer.

Automatic themes

A single data-theme value on the root HTML element activates one of two CSS systems. localStorage preserves the choice across pages.

Google Maps + offline fallback

The main map uses a Google Maps embed that moves to the exact coordinates of the selected roadbook stop. Route-section links open turn-by-turn directions without requiring a site API key. A coordinate-generated SVG remains available as an offline fallback.

Generic HTML vocabulary

The site uses semantic sections, articles, tables, details, buttons, links and data attributes. JavaScript enhances rather than replaces document structure.

8. Image and copyright strategy

Copyrighted film stills are not bundled. Each location has an original SVG orientation illustration, created for this project and labelled as a shot guide. For final publication, add your own field photography or properly licensed images to that location's photo gallery, and preserve captions and source information.

9. Photo gallery model

One unbounded pile per location

Each location has a gallery array in data/locations.json — a list of { "src": "path/to/photo.jpg", "caption": "..." } objects. There is no fixed frame count: add one photo or twenty, mixing movie stills and your own on-site photography freely. The page renders whatever is in the array as a grid, with a click-to-enlarge lightbox.

Camera-match guide stays separate

The original SVG orientation illustration (the "shot guide") is kept as its own element next to the gallery, since it serves a different purpose: it is a diagram of camera direction, not documentary evidence, so it should not be mixed into the pile of real photographs.

Why not a fixed two-image comparison

An earlier draft of this page paired exactly one "movie still" slot with one "real photo" slot. That forced every location into the same rigid comparison even where multiple angles, multiple visits or multiple film appearances existed. The gallery model removes that constraint entirely.
